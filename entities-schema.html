2. Физические границы: где живёт каждая сущность?

Самая частая путаница: Temporal Server НЕ содержит и НЕ выполняет ваш Java-код! Нажимайте на любой из 3 узлов архитектуры или каналы связи gRPC, чтобы подсветить детали.

Уровень 1 • Инициатор HTTP :8081 / CLI

🌐 1. КЛИЕНТ (REST Controller / UI / CLI)

Любой сервис или контроллер, который общается с Temporal по gRPC для управления процессами.

Использует SDK-клиенты:
  • WorkflowClient — старт, сигналы, запросы
  • ScheduleClient — управление расписаниями
  • ActivityCompletionClient — колбэк по токену
Что делает:
  • Запускает Workflow (start / execute)
  • Шлёт Signals, Queries, Updates
  • Завершает внешние Activity по TaskToken
Уровень 2 • Оркестратор gRPC :7233

🏛️ 2. TEMPORAL SERVER + БД

❗ НЕ СОДЕРЖИТ И НЕ ВЫПОЛНЯЕТ ВАШ JAVA-КОД!
💾 Хранит в БД (PostgreSQL):
  • • Namespaces
  • • Event History (#1..#N)
  • • Mutable State
  • • Search Attributes & Memo
⚡ Управляет в памяти:
  • • Task Queues (Matching)
  • • Timer Queue (Будильники)
  • • Schedules (Расписания)
  • • Retry Backoff Timers
Уровень 3 • Исполнитель кода Long Polling → :7233

👷 3. WORKER PROCESS (Spring Boot)

Ваше приложение. Сами воркеры вытягивают задачи с сервера по gRPC Long Polling (сервер не стучится в воркер снаружи!).

🧠 Workflow Worker
  • • Крутит @WorkflowImpl
  • • Делает детерминированный Replay
  • • Вызывает Local Activities
  • • Считает Saga и CancellationScope
🛠️ Activity Worker
  • • Крутит @ActivityImpl
  • • Ходит в БД, HTTP, брокеры
  • • Шлёт Heartbeat(progress)
  • • Генерирует TaskToken

Поток взаимодействия через gRPC (порт 7233)

Важно: Воркерам не нужен открытый входящий порт!

И Клиент, и Worker Process сами открывают исходящее gRPC-соединение к Temporal Server (:7233). Когда появляется задача в Task Queue, Worker моментально получает её через уже открытый Long Polling запрос, выполняет кусок Java-кода и возвращает ответ серверу.

Наведите курсор или кликните на любой узел графа, чтобы подсветить только его прямые связи (`1:1`, `1:N`, `N:1`) и отфильтровать таблицу ниже.

Показаны все сущности

4. Симулятор: как 1 строчка кода превращается в цепочку задач

Пошагово пройдите вызов standardActivities.callFlakyExternalService("Payment", 2) с 2 сбоями и успешной 3-й попыткой.

Шаг 1 / 7
// ShowcaseWorkflowImpl.java:
String res = standardActivities.callFlakyExternalService("Payment", 2);
🧠 Workflow Worker выполняет код до вызова Activity...
1. 🧠 Workflow Worker
Доходит до строки вызова ActivityStub и формирует команду ScheduleActivityTask.
2. 🏛️ Temporal Server
Ожидает команд от воркера.
3. 📋 Task Queue
Очереди ShowcaseTaskQueue пусты.
4. 🛠️ Activity Worker
Слушает Activity Sub-Queue по Long Polling.

📜 Неизменяемый Event History в БД (Save Points)

Важно: ретраи (#1, #2) НЕ засоряют историю!

⚡ Сравнение: Обычная Activity vs Local Activity

🛠️ Обычная Activity (Standard Activity)
Workflow Worker ──► Server (БД + Task Queue) ──► Activity Worker (любой хост)

Полная изоляция, бесконечные ретраи, балансировка нагрузки между хостами, но +10..30 мс на сеть и БД.

⚡ Local Activity (Локальная в памяти)
Workflow Worker ──► Вызов в том же JVM-процессе ──► Запись итога в History

Задержка < 1 мс, не нагружает Matching Service. Идеально для быстрых проверок (fastLocalCheck) и коротких шагов.

5. Интерактивная диаграмма состояний (Жизненный цикл Workflow Execution)

Нажимайте на кнопки триггеров, чтобы переводить процесс из одного состояния в другое (включая вложенные подсостояния внутри Running и «Машину времени» Workflow Reset).

Текущее состояние Running (ExecutingWorkflowTask)

Процесс запущен через WorkflowClient.start(). Сейчас Workflow Worker активно выполняет ваш Java-код до ближайшей точки ожидания.

Доступные переходы (нажмите для срабатывания):
🟢 RUNNING (Активный процесс) WorkflowClient.start() / Schedule trigger
⚡ ExecutingWorkflowTask
Воркер крутит код до точки ожидания (несколько миллисекунд)
⏳ WaitingOnServer
Ждёт Activity / Timer / Signal / ChildWorkflow (секунды, дни, месяцы)
🔄 ContinuedAsNew
Текущий Run закрыт, мгновенно создан новый RunId с чистой историей
──► Новый Running
✅ Completed
Успешный возврат результата
💥 Failed
Необработанное исключение (можно сделать Reset!)
🛑 Canceled
Корректная отмена через Scope
⚡ Terminated
Убит без выполнения кода
⌛ TimedOut
Истёк таймаут выполнения
